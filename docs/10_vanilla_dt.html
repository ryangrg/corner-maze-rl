1.Configuration

Defines every knob the rest of the notebook reads. No side effects beyond a printed banner.

This is the only cell you typically edit. Everything downstream reads from these globals: cells 2–14 import them by name. Re-running cell 1 alone doesn't update earlier in-memory globals — re-run top-to-bottom after edits.

Experiment identity

Subject + group

TRAINING_GROUP is the short code; Cell 2 maps it via GROUP_ALIASES to the canonical training_group label stored in subjects.parquet ('PI', 'PI+VC', 'VC', 'PI+VC_f1'). The cell asserts every subject in SUBJECTS matches the group.

Cost (locked)

@dataclass(frozen=True)
class CostConfig:
    terminal_reward: float = 1.0
    step_cost:       float = 0.001
COST = CostConfig()

Part of the run identity: training and inference use the same (R, c). The training-time RTG is rtg = R − c·actions_to_reward; inference re-uses the same constants for re-anchoring and within-trial drift. Changing these for inference without retraining would shift the input distribution off the trained manifold.

These are not the env's actual rewards. The env emits -0.0005 (forward/pickup/pause), -0.001 (turn), +1.061 (correct well). See Cell 7's RTG management note for why we ignore env rewards.

LAST_N_ACQ_FOR_RTG = 2     # trailing acq sessions per subject feed EXPECTED_OPT_LEN

Windowing

K = 128     # context length; kzl gym default is 20

Bumped from kzl's 20 because rat sessions are 2-3× longer than kzl episodes and rat behavior shows cross-trial strategy. A K=128 window typically spans 1-3 trials → DT sees cross-trial context.

Memory scales as O(K²) in attention scores. K=128 → ~150 MB attention/layer/batch at default config. K=256 → 600 MB. Cell 10's _memory_precheck guards against blowing the device.

(c) Canonical-frame rotation

PI / PI+VC subjects are rotated so the cue lands at North in every session — matching the rat's internal (path-integration) frame. VC subjects skip rotation because their cue rotates across sessions by design (rotating cue is the VC training signal).

ROTATE_TO_CANONICAL = GROUP_ALIASES[TRAINING_GROUP] in ('PI', 'PI+VC', 'PI+VC_f1')

# Per-session: n_rotations = cue index of first trial (0=N → 0 rotations, 1=E → 1, ...)
def _compute_n_rotations(trial_configs):
    cues = set(tc[1] for tc in trial_configs)
    if len(cues) != 1:
        return None          # multi-cue session — defensively drop
    return list(cues)[0]

Rotation formulas (single 90° CCW step, screen y-down)

Direction sign correction The legacy implementation in corner-maze-rl-legacy/yoking/rotate_to_canonical.py:62 uses (d + n) % 4. That's wrong for n ∈ {1, 3} — only accidentally correct for n=2 due to 180° symmetry. We use (d − n) % 4. Empirical proof: agent at (8, 6) facing E (d=0) walks forward to (9, 6). One CCW rotation maps (8,6)→(6,4) and (9,6)→(6,3) — a step in −y = direction N = 3. Legacy gives (0+1)%4 = 1 = S (180° off). Corrected formula gives 3 = N. The legacy bug stayed buried because its validation only checked rewarded positions, never directions.

What rotation actually does, per encoder

encodereffect on DT input stream
pose_visualNo-op in practice. pose_visual.npz already collapses all 4 rotational variants of any pose to the same embedding row (4536→295 indirection). Verified across 491K rows: every (orig, rotated) pair maps to the same state_idx.
image_cnnNo-op. minigrid_views.npz views are byte-identical across rotational equivalents (the 13×13 maze is 4-fold rotationally symmetric).

We rotate uniformly anyway as a defensive choice — the rotation is cheap and we don't want to remember which encoders need it.

(d) Per-trial timestep — deliberate deviation from kzl

# Trial-start rule: t starts a trial iff t == 0 OR a2r[t] > a2r[t-1]
trial_start_mask = np.concatenate([[True], a2r[1:] > a2r[:-1]])
trial_id          = np.cumsum(trial_start_mask) - 1
trial_timestep    = np.arange(L) - trial_start_positions[trial_id]

kzl's embed_t indexes by step within episode (their MuJoCo episodes are ≤1000 steps). For our 2000-3000-step rat sessions that's the wrong unit:

  • Per-session timestep puts almost zero samples on high positions (only sessions long enough to reach step 1500 train embed_t[1500]).
  • Per-trial timestep puts ~32 trials/session × N sessions ≈ 100s of samples on every embed_t[i] for i < typical_trial_len.
  • MAX_EP_LEN shrinks from ~3000 to ~250 → embedding table is ~12× smaller.
  • embed_t[5] consistently means "5 steps into a trial," not "5 steps into wherever this session started."

(e) Per-step RTG (analytical, per-trial-relative)

rtg = COST.terminal_reward - COST.step_cost * a2r     # shape (L,) float32

For each step, RTG = R − c · actions_to_reward. The signal climbs from R − c·L_trial at trial start to R at the reward step, then jumps back down at the next trial. Not a sum of future rewards (that's the MuJoCo definition kzl uses). This is an analytical training signal — same constants used at inference (Cell 7) for re-anchoring + smooth-climb.

4.RatWindowDataset + DataLoaders

Slides a length-K window over each session's per-step arrays. Windows never cross session boundaries; within a window, multiple trials can appear.

The dataset

class RatWindowDataset(Dataset):
    def __init__(self, sessions, K):
        self.K = K
        self.sessions = sessions
        # Pre-compute (session_idx, start_step) for every valid window position.
        self.index = []
        for i, s in enumerate(sessions):
            n_win = max(0, s['length'] - K + 1)
            self.index.extend((i, start) for start in range(n_win))

    def __getitem__(self, i):
        sess_i, start = self.index[i]
        sess = self.sessions[sess_i]
        end = start + self.K
        return {
            'state_idx':      torch.from_numpy(sess['state_idx'][start:end]).long(),
            'action':         torch.from_numpy(sess['action'][start:end]).long(),
            'rtg':            torch.from_numpy(sess['rtg'][start:end]),
            'trial_timestep': torch.from_numpy(sess['trial_timestep'][start:end]).long(),
        }

Per batch element

tensorshapedtypenote

make_loaders(unit, seed)

def make_loaders(unit, seed):
    sessions = sessions_for(unit.subjects)
    usable   = [s for s in sessions if s['length'] >= K]
    full_ds  = RatWindowDataset(usable, K)
    n_val    = max(1, int(len(full_ds) * VAL_FRAC))
    n_train  = len(full_ds) - n_val

    # Two distinct generators so split and shuffle don't share state
    g_split   = torch.Generator().manual_seed(seed)
    g_shuffle = torch.Generator().manual_seed(seed + 10_000)
    train_ds, val_ds = random_split(full_ds, [n_train, n_val], generator=g_split)

    return (
        DataLoader(train_ds, batch_size=BATCH_SIZE, shuffle=True,  drop_last=True,
                   generator=g_shuffle, ...),
        DataLoader(val_ds,   batch_size=BATCH_SIZE, shuffle=False, drop_last=False, ...),
        full_ds,
    )
Split semantics Random window split (kzl-style). Train and val windows from the same session can overlap by K−1 steps — the val loss is "next-action prediction in a region the model has nearly seen." Useful for hyperparameter tuning + overfitting detection, but not a true held-out benchmark. The honest generalization signal comes from the env-side probes (Cell 9).

Reproducibility

The two generators are seeded from the same seed with different offsets so the split and the in-epoch shuffle order are both reproducible per (unit, seed). The smoke test at the bottom of the cell verifies: running make_loaders(unit, 0) twice produces identical first batches.

5.Build DT model (kzl-faithful port)

Three components composed: state encoder factory, custom GPT2 transformer body, and the DTEmbedding that interleaves (R, s, a) tokens per step.

State encoder factory

def make_state_encoder(encoder_type, state_lookup, hidden_dim, freeze):
    if encoder_type in ('pose_visual', 'grid_cell'):
        # .clone() decouples the Parameter's storage from STATE_LOOKUP so that
        # FREEZE_ENCODER=False updates don't bleed across seeds via the shared numpy buffer.
        w = torch.from_numpy(state_lookup).float().clone()
        return nn.Embedding.from_pretrained(w, freeze=freeze)
    elif encoder_type == 'image_cnn':
        return ImageCNNEncoder(state_lookup, hidden_dim)

For frozen lookups the encoder is just an nn.Embedding initialized from the npz; gradients don't flow through it. For image_cnn we instantiate the trainable CNN (3→16 conv → flatten → Linear → 60D).

Why the .clone() matters

Without .clone(), the storage chain STATE_LOOKUP (numpy) → torch.from_numpy (shared) → .float() (no-op on already-float32, shared) → nn.Parameter (shared via detach) means the model's embedding.weight tensor and the global numpy STATE_LOOKUP point at the same float32 buffer.

With FREEZE_ENCODER=True this is harmless — nothing modifies the weights. With FREEZE_ENCODER=False it's a silent cross-seed contamination bug: AdamW's in-place updates on embedding.weight land in STATE_LOOKUP, so seed 1's make_dt() initializes from seed 0's trained weights instead of the original grid-cell vectors. Each seed inherits the previous seed's modifications and the N_RUNS independence required for stratified-bootstrap CIs (Cell 12) silently breaks.

The .clone() costs ~110 KB per seed (one fresh copy of the 295×60 or 484×60 lookup) and guarantees each seed starts from the pristine pretrained values regardless of freeze mode. Mandatory before flipping FREEZE_ENCODER=False; harmless for the default frozen runs. ImageCNNEncoder doesn't need the same fix — its uint8 → float32 conversion in .float() forces a genuine copy at construction.

Causal self-attention

class CausalSelfAttention(nn.Module):
    def __init__(self, d_model, n_heads, dropout):
        self.qkv      = nn.Linear(d_model, 3 * d_model)
        self.out_proj = nn.Linear(d_model, d_model)
        ...

    def forward(self, x, return_attn=False):
        B, T, C = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = q.view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        k = k.view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        v = v.view(B, T, self.n_heads, self.d_head).transpose(1, 2)
        scores = (q @ k.transpose(-2, -1)) / (self.d_head ** 0.5)
        causal_mask = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
        scores = scores.masked_fill(causal_mask, float('-inf'))
        attn = F.softmax(scores, dim=-1)
        out = (attn @ v).transpose(1, 2).contiguous().view(B, T, C)
        return (self.resid_drop(self.out_proj(out)),
                attn if return_attn else None)

Why hand-roll vs HuggingFace?

  • No internal positional embedding. kzl zeroes out HF's wpe layer; we just omit it. Position info enters only via embed_t.
  • Attention extraction for Cell 13 diagnostics — returning attn as a tensor is trivial here, requires hooks with HF.
  • No HF dep — saves ~700MB of transformers wheel.

The mask is built fresh from the sequence length T inside the forward call — so variable-length T at inference (Cell 7) works without padding.

Block + body

class GPT2Block(nn.Module):
    def forward(self, x, return_attn=False):
        a, attn = self.attn(self.ln_1(x), return_attn=return_attn)
        x = x + a
        x = x + self.mlp(self.ln_2(x))
        return x, attn

Pre-LayerNorm pattern (LN before attn / LN before MLP). MLP is 4× expansion with GELU.

DTEmbedding — token interleave

class DTEmbedding(nn.Module):
    def forward(self, rtg, state_idx, action, trial_timestep):
        B, K = rtg.shape
        t_e = self.embed_t(trial_timestep)                       # (B, K, H)
        r_e = self.embed_R(rtg.unsqueeze(-1)) + t_e           # (B, K, H)
        s_e = self.state_encoder(state_idx)  + t_e           # (B, K, H)
        a_e = self.embed_a(action)           + t_e           # (B, K, H)
        # Interleave along a new axis, flatten to (B, 3K, H)
        stacked = torch.stack([r_e, s_e, a_e], dim=2)            # (B, K, 3, H)
        stacked = stacked.reshape(B, 3 * K, -1)                # (B, 3K, H)
        return self.drop(self.embed_ln(stacked))

The torch.stack(..., dim=2) followed by reshape(B, 3*K, -1) interleaves correctly:

position 0 → R₀
position 1 → s₀
position 2 → a₀
position 3 → R₁
position 4 → s₁
position 5 → a₁
...

Matches kzl token order. embed_t is added to all three modality streams so each token at time-step k carries the same positional anchor.

Action head

def forward(self, rtg, state_idx, action, trial_timestep, return_attn=False):
    x = self.embedding(rtg, state_idx, action, trial_timestep)    # (B, 3K, H)
    x, attns = self.body(x, return_attn=return_attn)                # (B, 3K, H)
    x_state = x[:, 1::3, :]                                            # (B, K, H) — state tokens at 1, 4, 7, ...
    logits  = self.action_head(x_state)                              # (B, K, NUM_ACTIONS)
    return (logits, attns) if return_attn else logits

The action prediction reads from state-token positions. With the causal mask, the state token at step k has seen R[0..k], s[0..k], a[0..k-1] — exactly the right context for predicting a[k]. CE loss in Cell 6 supervises every K position in each window.

Parameter accounting (default config)

  • embed_t (MAX_EP_LEN × HIDDEN_DIM) — ~250 × 60 = 15 K params
  • Body: N_LAYERS × 12 × HIDDEN_DIM² ≈ 3 × 12 × 60² = 130 K params
  • State encoder (pose_visual): frozen, 295 × 60 = 17.7 K params (not counted in trainable)
  • Trainable total: ~145 K params (~0.6 MB fp32)

Per-batch step

        rtg=batch['rtg'],
        state_idx=batch['state_idx'],
        action=batch['action'],
        trial_timestep=batch['trial_timestep'],

                            batch['action'].reshape(-1))

    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    last_grad = torch.nn.utils.clip_grad_norm_(trainable, GRAD_CLIP).item()
    optimizer.step()
    scheduler.step()
    global_step += 1
  1. Move the batch to device.
  2. Forward → action logits (B, K, NUM_ACTIONS).
  3. CE loss against the rat's actions over all K positions in the window. The autoregressive structure means token k's loss is supervised by action[k] and gradients flow back through the (R, s, a) history before it.
  4. Backward, clip grad norm at GRAD_CLIP=0.25, AdamW step, LR scheduler step (linear warmup over WARMUP_STEPS).

Cue-N anchoring (_trained_goal_for_subject)

def _trained_goal_for_subject(subject):
    ori = _SUBJECT_META[subject]['cue_goal_orientation']
    return ori.split('/')[1]

For CM016 ('N/SE'), returns 'SE'. The env's trial generator interprets start_goal_location='SE' as gli=1, which (combined with cue_goal_orientation='N/SE') places cue at N, goal at SE — the canonical training frame.

Why this anchor exists: the rat's training data was rotated to canonical-N (Cell 3). To preserve that frame at inference, the env must run canonical-frame trials. Without this anchor the env picks a random gli and trial_configs are in arbitrary rotational orientations the DT didn't train on.

The episode loop

for t in range(max_steps):
    ctx_K = min(len(rtg_buf), K)
    # slice the rolling buffers to the last ctx_K entries, batch them up
    rtg_t   = torch.tensor(rtg_buf[-ctx_K:],   ...).unsqueeze(0)
    state_t = torch.tensor(state_buf[-ctx_K:], ...).unsqueeze(0)
    action_t= torch.tensor(action_buf[-(ctx_K-1):] + [0], ...).unsqueeze(0)
    tt_t    = torch.tensor(tt_buf[-ctx_K:],    ...).unsqueeze(0)

    logits = model(rtg_t, state_t, action_t, tt_t)
    last_logits = logits[0, -1, :]
    if deterministic: action = int(last_logits.argmax().item())
    else:             action = int(torch.multinomial(torch.softmax(last_logits / temperature, -1), 1).item())

    obs, reward, terminated, truncated, info = env.step(action)

    new_trial_count = info.get('trial_count', prev_trial_count) or prev_trial_count
    trial_just_ended = new_trial_count > prev_trial_count
    if trial_just_ended:
        n_trials += 1
        next_rtg = float(target_rtg)        # re-anchor at trial boundary
        next_tt  = 0
    else:
        next_rtg = rtg_buf[-1] + COST.step_cost   # smooth within-trial climb
        next_tt  = min(tt_buf[-1] + 1, MAX_EP_LEN - 1)
    prev_trial_count = new_trial_count

    # ... append next_state_idx, next_rtg, next_tt to buffers, log everything ...
    if terminated or truncated: break

RTG management — why we ignore env reward

Training RTG = R − c·actions_to_reward is an analytical per-trial signal, not a sum of future rewards. The env emits actual rewards (-0.0005 step / -0.001 turn / +1.061 goal) that don't match. Using kzl's next_rtg = rtg − reward rule would drift the DT off its training distribution.

So we maintain RTG analytically:

  • Within a trial: next_rtg = current_rtg + COST.step_cost. Smooth upward drift mirroring the training-time signal.
  • At trial boundary (detected via info['trial_count'] incrementing): next_rtg = target_rtg. Re-anchor to the conditioning target (INFERENCE_RTG by default).

Variable-length context

Steps 0..K-1 don't have a full K-token history yet. Rather than zero-padding (kzl's approach for fixed-shape input), we accept variable T = 3 × ctx_K where ctx_K = min(t+1, K). The causal mask is built fresh inside attention from the actual T. Works because there's no internal positional embedding to be confused by shorter sequences.

The action buffer needs a placeholder for the current position (the DT hasn't predicted it yet). We append 0 as a stand-in; the causal mask ensures the model never reads it.

Memory pre-check

def _estimate_dt_peak_memory_mb():
    # Dominant cost: per-layer attention scores: B × n_heads × (3K)² × 4 bytes
    T = 3 * K
    attn_per_layer_mb   = (BATCH_SIZE * N_HEADS * T * T * 4) / (1024 ** 2)
    hidden_per_layer_mb = (BATCH_SIZE * T * HIDDEN_DIM * 4) / (1024 ** 2)
    mlp_per_layer_mb    = (BATCH_SIZE * T * (HIDDEN_DIM * 4) * 4) / (1024 ** 2)
    fwd_act_mb     = N_LAYERS * (attn_per_layer_mb + hidden_per_layer_mb + mlp_per_layer_mb)
    bwd_overhead_mb = fwd_act_mb * 1.5
    n_params_approx = MAX_EP_LEN * HIDDEN_DIM + N_LAYERS * 12 * HIDDEN_DIM * HIDDEN_DIM
    params_mb    = n_params_approx * 4 / (1024 ** 2)
    optimizer_mb = params_mb * 2                  # AdamW = 2 floats per param
    return fwd_act_mb + bwd_overhead_mb + params_mb + optimizer_mb + 100  # +100MB headroom

The acq gate

def _acq_max_correct(seed_dir_path):
    traj = pd.read_parquet(Path(seed_dir_path) / 'acq_trajectory.parquet')
    well_locs = {tuple(map(int, loc)) for loc in WELL_LOCATIONS}
    best = 0
    for _keys, sub in traj.groupby(['temp_label', 'repeat_idx'], sort=False):
        # Disqualify rollouts that truncated before running the full session
        if int(sub['trial_id'].nunique()) < ACQ_INFERENCE_TRIALS:
            continue
        n_correct = 0
        for _tid, trial in sub.groupby('trial_id', sort=False):
            rewards = trial['env_reward'].to_numpy()
            if not (rewards > 0.5).any(): continue            # trial didn't reach goal
            prev_at_well, wrong = False, False
            for x, y, r in zip(trial['grid_x'], trial['grid_y'], rewards):
                cur_at_well = (int(x), int(y)) in well_locs
                if cur_at_well and not prev_at_well and r < 0.5:
                    wrong = True; break                          # wrong-well entry before goal
                prev_at_well = cur_at_well
            if not wrong: n_correct += 1
        best = max(best, n_correct)
    return int(best)

Per-seed gate, two-part rule: a (temp, repeat) rollout qualifies only if it (a) ran the full ACQ_INFERENCE_TRIALS-trial session AND (b) achieved ≥ ACQ_PASS_COMPLETED_TRIALS strictly-correct trials. A correct trial reaches the goal well without ever entering a non-goal well first. Wrong-well visits don't appear in env_reward (the env only sets trial_score=0 internally), so detection is positional against WELL_LOCATIONS in the acq trajectory parquet. A rollout that solves 31/31 trials perfectly but truncates before trial 32 fails the gate — partial sessions can't pass, regardless of correct count.

Skipping probes for failed seeds isn't a sample-size loss — it's an interpretability safeguard. A "novel-route success rate of 0%" on a broken DT tells you nothing about generalization.

Failure policy Fail-fast. Any exception in training / acq / probes propagates and halts the whole sweep — you see the traceback immediately. No silent skips. Re-run after fixing the issue (previous seeds' artifacts persist on disk; the sweep will overwrite them on re-run).

The per-seed → cross-seed pattern

For every metric, compute per-seed value first, then aggregate across seeds. IQM is the central statistic; p25/p50/p75 give the uncertainty band. Pooled rate (sum completed / sum attempts) reported as a sanity check.

def _iqm(values):
    """Interquartile mean: mean of values within [p25, p75]."""
    arr = np.asarray(values, dtype=float)
    if len(arr) == 0: return float('nan')
    q25, q75 = np.percentile(arr, [25, 75])
    in_iqr = arr[(arr >= q25) & (arr <= q75)]
    return float(in_iqr.mean()) if len(in_iqr) else float(arr.mean())

Why rliable

The per-seed × per-condition matrix is exactly what rliable's stratified bootstrap is designed for. With N=5 seeds × many (probe, tag) tasks, naive percentile bands underestimate uncertainty.   • Play / Pause — async loop calls _advance_one_step at speed_slider.value steps/sec.
  • ← Back — rewind one step by env.reset + replay forward to target (CornerMazeEnv has no rewind primitive; ~1.3 ms/step).
  • Step → — manual single-step advance.

Renders

Allocentric maze frame from env.get_allocentric_frame(tile_size=23). Eye images from env._pose_to_left_eye / _pose_to_right_eye lookups (populated by env._load_embeddings()). Single-line session label under the maze for orientation.

Why these knobs

  • N_RUNS drives statistical power on cross-seed plots — headline (5) gives meaningful IQR on rliable bootstrap CIs.
  • N_EPOCHS drives training quality — smoke (2) is barely-trained; iteration (15) finds a real minimum; headline (50) trains to convergence with early-stop available.
  • *_TEMPS lists determine inference modes — None=argmax, 1.0=paper-faithful sampled.
  • *_PROBA_REPEATS controls how many sampled rollouts per temp — headline (5) is enough for meaningful stratified bootstrap CI.
