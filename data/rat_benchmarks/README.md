# Rat behavioral benchmarks

Per-rat acquisition + probe metrics for the **48 manuscript-scope subjects** across the 4 training groups (PI, PI+VC, PI+VC_f1, VC). Generated by [`scripts/extract_rat_benchmarks.py`](../../scripts/extract_rat_benchmarks.py) from two sources:

- **Behavioral metrics** (sessions-to-acquire, probe rates): sibling repo `corner-maze-analysis/data/processed/`.
- **Step counts** (`n_steps_to_acquire`): this repo's yoked dataset at `data/yoked/dataset/sessions.parquet`, using the `n_actions` column (which matches the real-pretrial action stream exactly).

Mirrors the agent-side metrics computed in [notebook 03A](../../notebooks/03A_ppo_minigrid_cnn.ipynb) so rat vs. agent comparisons use identical denominators, tag definitions, *and* step-counting conventions.

## Regenerate

```bash
python scripts/extract_rat_benchmarks.py
```

Requires `corner-maze-analysis` repo at `~/Code/python-dev/corner-maze-analysis/` (path hard-coded in the script). Re-runs are cheap (~1s).

## Schema — `per_subject.parquet` (48 rows)

| column | type | notes |
|---|---|---|
| `subject_id` | int | analysis-repo primary key (non-sequential, gaps from pilots) |
| `name` | str | e.g. `CM001` |
| `training_group` | str | `PI` / `PI+VC` / `PI+VC_f1` / `VC` |
| `sex` | str | `M` / `F` |
| `n_sessions_to_acquire` | int | count of `session_experiment_phase == 'Acquisition'` sessions; matches legacy `sessions_to_acq` |
| `n_steps_to_acquire` | int / NaN | sum of yoked-dataset `n_actions` across this subject's acquisition sessions; NaN if no yoked data exists for the subject. Real-pretrial action stream — see note below. |
| `n_yoked_acq_sessions` | int | count of yoked acquisition sessions present for the subject; equals `n_sessions_to_acquire` when yoking is complete. Audit column for catching upstream gaps. |
| `acquired` | bool | True iff rat has any probe-phase session (proxy for "advanced to probes per protocol"); all 48 in-scope rats acquired |
| `n_probe_sessions` | int | total probe sessions (Novel Route + Reversal + Rotation + No Cue) |
| `rate_novel_route` | float | `n_correct_novel_route / n_possible_novel_route`; NaN if no Novel Route sessions |
| `n_correct_novel_route` | int | sum of correct novel-tagged trials across all the rat's Novel Route sessions |
| `n_possible_novel_route` | int | `n_sessions_novel_route × 16` |
| `n_sessions_novel_route` | int | number of Novel Route sessions for this rat |
| `rate_dark`, `n_correct_dark`, `n_possible_dark`, `n_sessions_dark` | … | denominator = 32 / session |
| `rate_rotate`, `n_correct_rotate`, `n_possible_rotate`, `n_sessions_rotate` | … | denominator = 16 / session |
| `rate_reversal`, `n_correct_reversal`, `n_possible_reversal`, `n_sessions_reversal` | … | denominator = 64 / session |

## Trial-tagging derivation

The new `trials.parquet` in corner-maze-analysis does not have a `trial_type` column (the legacy `build_pandas_table.py` computed it). We derive tags from `trial_number` + `start_arm`:

- **Novel Route — novel-tagged**: trials with `start_arm` NOT in the set of start_arms appearing in the session's first 16 trials. Gives 16 novel-start trials in a typical 40-trial Novel Route session (verified for CM001 / Fixed Cue 2a). Matches legacy `novel_route_score()` semantics ([`legacy/scripts/build_pandas_table.py:505`](../../../corner-maze-analysis/legacy/scripts/build_pandas_table.py)).
- **Reversal — reversal-tagged**: trials with `trial_number > 16` (first 16 are pre-probe on original contingency). Matches the legacy `reversal_block_scores()` / `std_trials_crit()` pre-probe convention.
- **Dark / Rotate**: all trials count (no warmup, no tag filter) — matches `num_no_cue_trials = 32` ([build_pandas_table.py:1346](../../../corner-maze-analysis/legacy/scripts/build_pandas_table.py)) and `num_rotation_trials = 16` ([build_pandas_table.py:1387](../../../corner-maze-analysis/legacy/scripts/build_pandas_table.py)).

A trial is **correct** iff `errors == 0` (legacy convention).

## Caveats / gotchas

1. **`acquired` is a proxy.** The rat-side pipeline does *not* encode an explicit "reached criterion" flag — rats that made it to probes are presumed to have acquired per protocol. All 48 in-scope rats have probe sessions, so `acquired=True` for everyone. There is no rat-side "did not acquire" category in this dataset (those animals are upstream-excluded).
2. **Sessions-to-acquire vs the RL `TOTAL_SESSIONS` cap.** Rat medians are 5–9 sessions (≪ the agent's `TOTAL_SESSIONS=50` cap). The cap was set generously — the rat-comparable expectation is single-digit sessions, not dozens.
3. **`n_steps_to_acquire` uses the real-pretrial yoked action stream.** `sessions.parquet` in the yoked dataset has a pre-computed `n_actions` column that exactly matches `actions_real_pretrial.parquet` row counts (verified across all 549 acquisition sessions). The synthetic-pretrial table covers a few more sessions but uses fabricated pretrial actions for sessions where real pretrial data wasn't available — for "what would a rat's MiniGrid step count actually be" we want the real-pretrial number. Note: agent `total_steps` includes pretrial + trial + ITI within each episode, so this is apples-to-apples with `n_steps` in the agent's `acq_df`. Rat step totals are typically 13–17k (median ~7 sessions × ~2,100 steps/session), well below the agent's per-episode `max_steps` cap of 11,077 — rats use far less than the worst-case time-budget per session.
4. **PI and VC have no Dark or Rotate probes** per protocol. `rate_dark` / `rate_rotate` are NaN for those groups by design; don't fill or impute.
5. **PI+VC_f1 sample size is 6**, so per-group means are noisy. Treat individual-rat scatter as the more honest signal.
6. **Novel-tagged inference relies on warmup-start convention.** If a Novel Route session has a non-standard warmup structure (e.g., novel starts in trials 1–16), our heuristic will mis-label. The 6 standard probe session_types in the table above all follow the "trials 1–16 = trained starts, 17+ = mix of trained + novel" pattern, verified spot-check.
7. **Yoking gap audit.** `n_yoked_acq_sessions` should equal `n_sessions_to_acquire` for every subject. As of 2026-05-20 all 48 in-scope rats have complete yoking coverage. If a future yoking regeneration introduces gaps, the extraction script prints a `WARNING` block listing affected subjects, and `n_steps_to_acquire` will undercount for those rats — check the audit column before reporting.
